# Windows 11 主菜单快捷任务

[English](NATIVE-MENUS.md) · [命令设置](QUICK-TASKS.zh-CN.md)

原生扩展将带软件图标的“发送Agent Pal任务”放入 Windows 11 第一层右键菜单，支持文件夹、文件夹空白处和桌面。只有一个有效伙伴任务绑定时直接打开；多个时才展开，各子项已绑定伙伴和命令；没有有效绑定时隐藏入口。

## 启用

1. 安装包含 `shell` 组件的版本。
2. 打开 **默认设置 → 常规 → 管理右键快捷任务…**。
3. 勾选 **直接显示在 Windows 11 主菜单**，选择位置与伙伴绑定，保存。
4. 完成必要的系统授权。程序注册身份包并校验原生标题、图标和启用状态后才显示成功。

失败时点击错误状态查看完整系统原因。注册失败会恢复原来的命令定义与入口，不会只保存了 JSON 就显示注册成功。

本试用包使用专用代码签名测试证书。当前测试系统拒绝仅信任“当前用户”证书，因此启用时需要批准将这张公钥证书加入 **本地计算机 → 受信任的人**。安装器和设置不会静默导入；不导入根证书，不修改开发者模式。私钥不可导出，也不包含在安装包和源码中。正式发布应使用目标系统认可的正式签名。

Windows 10 或未包含已签名身份包的源码构建，可选择兼容菜单；Windows 11 的兼容菜单位于“显示更多选项”。

## 实现与验证

- 使用原生 C++ `IExplorerCommand` 与独立 COM 宿主；打开菜单时只读少量当前用户注册表配置，不加载托管主程序，不运行 Claude 或扫描文件。
- 每种 Explorer 场景只注册一个自适应入口；64 个稳定绑定槽支持更新配置后直接生效，不需要重打身份包。桌面和文件夹空白处共用一个原生处理器，避免隐藏的预留命令造成自动分组。
- 空白处从实际 Explorer 文件夹视图解析路径；已打开的菜单在绑定被替换后会拒绝误调用。
- DLL 文件名包含内容散列，避免覆盖使用中的原生 DLL；卸载旧安装时不会删除新安装的菜单。
- 原生桥接测试使用模拟入口和测试专用 Explorer 站点，验证选中文件夹、文件夹背景、桌面、中文路径与绑定变更保护，不调用模型，也不自动操作真实桌面。

原生协议测试和签名通过，还需要目标机器成功注册身份包，并在实际 Explorer 中验收显示效果，才能视为主菜单功能验收完成。

身份包注册后，可在原生测试命令后增加 `-Registered`，验证 Windows 实际注册的独立 COM 宿主、调用与背景站点封送；默认模式直接加载 DLL。两种模式均使用预留临时绑定和模拟程序，不调用 Claude。

## 内网部署

公钥证书位于 `shell/agent-pal-preview.cer`，SHA-1 指纹为 `28144B7235A5F7EEE8886478791135913C8FA0EC`，到期日为 **2027 年 2 月 18 日**。它签署原生菜单 DLL 与身份包，不签署主程序和安装器；私钥不要分发到内网目标机。

每台 Windows 11 x64 目标机需由管理员批准将这张公钥证书加入 **本地计算机 → 受信任的人**，可离线完成。安装后，在快捷任务设置中启用主菜单。单位的软件管控策略仍可能另有限制，应在实际目标机验收。

长期内网部署应采用单位认可的代码签名身份并按单位流程统一分发信任。正式证书完全可以同时用于测试与发布，不必先使用自签名证书。本试用包没有可信时间戳，到期后新安装或重新安装身份包会受影响；参见[微软时间戳说明](https://learn.microsoft.com/en-us/windows/msix/package/signing-package-overview#timestamping)。

原生构建需要 x64 LLVM-MinGW、Windows SDK MakeAppx/SignTool、Python/Pillow 和代码签名身份；基础 WinForms 构建仍只需 .NET Framework。环境变量及命令见[英文构建说明](NATIVE-MENUS.md#build)。

参考：[微软原生菜单扩展](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/integrate-packaged-app-with-file-explorer)、[外部位置身份包](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/grant-identity-to-nonpackaged-apps)。
